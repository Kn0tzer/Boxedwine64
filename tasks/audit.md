How DXVK gates itself (verified from `dxvk_adapter.cpp` / `dxvk_device_info.h`):
`isCompatible()` → `capabilities.isSuitable()` checks apiVersion ≥ 1.3, required extensions
present, required features supported — else `Skipping: Device does not support required
feature 'X'` → `No adapters found`. Then `createDevice()` enables *all* queried extensions
and the full feature blob. Our bridge is lenient at create (ignores pNext + extension
names) so creation never fails — **the wall is the reporting side**.

| instance exts: surface + win32_surface (+debug_utils opt) | surface, xcb, xlib, headless — **no win32_surface, no debug_utils** | winevulkan surface creation has no target (see (d)) |

## (b) Memory — DXVK's allocator vs `mmapReserveAndMap` [P3, two P2-NOW one-liners]

What holds: per-alloc guest VA ranges (`vk64bridge.cpp:1498-1513`); aliasing works naturally
(mem+off per object); persistent maps are idempotent no-ops; `VK_WHOLE_SIZE` passes (no upper
size check); all mappable types are HOST_COHERENT so the missing
`vkFlush/InvalidateMappedMemoryRanges` (benign tail) is safe **iff that invariant is kept —
document it or a future "add non-coherent type" silently corrupts**.

Gaps:
- `memoryTypeBits` always `0xF`, alignment always 256, `bufferImageGranularity=1`. DXVK tolerates
  (selects by flags; granularity 1 is the most permissive lie). P4-harden, not P2.
- No dedicated-allocation (`*Requirements2` pNext ignored) → DXVK falls back. Fine.
- No `EXT_memory_budget` (not advertised → skipped). Fine.
- No external win32 memory (shared-resource interop). P4.
- Sparse: single family lacks SPARSE_BINDING; DXVK maps graphics/transfer/sparse queues
  (`createDevice` reads transfer+sparse mappings). **P3-verify** fallback behavior.
- **OOM never happens**: alloc always succeeds → DXVK never sees `ERROR_OUT_OF_DEVICE_MEMORY`
  → host OOM instead. P3: cap the 2 GB heap + fail honestly.
- `vkFreeMemory` → `munmap`: correct under churn, but DXVK churns little (startup allocs). P3 soak.

**Rank: P3.** Works for bring-up; breaks at game scale.

## (c) Threading + sync — deadlock fix and the submit wall [P2-NOW]

- **Hop under lock (fix now):** `vk64Bridge` holds `g_vkMutex` for the whole trap (`:848`);
  `vkQueuePresentKHR` → `emitFrameNow` → blocking `MAIN_THREAD_EM_ASM` (`:513`) executes
  *while holding it*. Cycle: worker holds mutex + blocks in hop; main thread needs the mutex
  (guest code on main via PROXY_TO_PTHREAD, xwire callbacks) → deadlock. Fix (~10 lines):
  build JSON under lock, release, hop outside. Rule: never block on main-thread work under
  `g_vkMutex`. Trap serialization itself is correct-but-coarse (all DXVK threads funnel
  through one mutex — P3 throughput measurement, per unknown #3).
- **Timeline semaphores (fix now):** DXVK puts a timeline `waitFence`/`signalFence` (u64) on
  *every* command-list flush (`dxvk_context.cpp`). Our `vkCreateSemaphore` ignores the
  `VkSemaphoreTypeCreateInfo` pNext (no counter stored); `vkSignalSemaphore`/
  `vkWaitSemaphores`/`vkGetSemaphoreCounterValue` don't exist → first flush dies in the benign
  tail. Fix (~40 lines): u64 counter on `Semaphore`; signal=max, wait/success immediate (valid
  under immediate execution); honor `VkTimelineSemaphoreSubmitInfo` pNext in submit.
- Binary semaphores: submit ignores wait/signal lists, acquire auto-signals, present ignores
  waits — self-consistent under immediate execution. P3: wire ordering when a 2nd family lands.
- **`vkQueuePresentKHR` never writes `pResults`** → DXVK reads garbage → phantom device-loss
  cascade at first present. **P2-NOW one-liner**: write `VK_SUCCESS` per swapchain.

## (d) Swapchain/present — wine surface missing [P2-NOW one item, rest P3]

- **No `vkCreateWin32SurfaceKHR` / `VK_KHR_win32_surface`** anywhere in shim or bridge. DXVK
  runs *inside wine*: `d3d11.dll` → `vulkan-1.dll` → `winevulkan.so` → `dlopen("libvulkan.so.1")`
  (our shim — good) → creates a **Win32** surface. Without the win32 path DXVK-on-wine cannot
  build a swapchain, period. **P2-NOW (~15 lines, mirrors the headless case).**
- Rest is P3: acquire round-robins, ignores timeout, always SUCCESS, auto-signals (consistent
  now); never `SUBOPTIMAL`/`OUT_OF_DATE`, `oldSwapchain` appears ignored → resize path needed
  (unknown #5); one format (B8G8R8A8_UNORM/SRGB) forces DXVK's hand (add R8G8B8A8 + SRGB variants
  P3); FIFO-only present modes (DXVK tolerates; MAILBOX/IMMEDIATE P4); no present_wait/present_id
  (not advertised → skipped, fine); image layout/ownership untracked (moot under immediate exec).

## (e) SPIR-V — the deepest risk [P2-NOW investigate, P3 execute]

- Reproduced in-repo: frag (SPIR-V 1.0, bound 48, glslang) → `InvalidId(40)`; vert → clean WGSL.
  Frag's distinguishing constructs: fragment derivatives (`OpDPdx`/`OpDPdy` 207/208) +
  explicit-LOD sampling (`OpImageSampleExplicitLod` 87) — both bread-and-butter in DXVK pixel
  shaders (HLSL `SampleBias`/gradient sampling lowers to exactly these). So the failure class
  blocks ~all DXVK pixel shaders, not just vkcube's.
- DXVK/dxc shaders add: SPIR-V 1.3+, 64-bit ints, **spec constants** (per-draw specialization —
  does naga spv-in accept `OpSpecConstant*` composites?), descriptor-indexing decorations,
  storage images + atomics, tessellation/geometry stages (widely used by D3D11 games),
  transform-feedback `Xfb` decorations (naga spv-in has no Xfb support), subgroup ops.
- Translator options: (1) upgrade naga past the fix if upstream fixed `InvalidId(40)` — check
  first, cheapest; (2) patch naga spv-in (needs naga source build — heavy); (3) **spirv-cross-wasm
  SPIR-V→GLSL + existing naga glsl-in** (C1 lane proves glsl-in works; spirv-cross is a
  known-quantity emscripten target); (4) Tint (heaviest). Slang is NOT a fallback — vendored
  `slang-wasm` exposes HLSL→WGSL only, no SPIR-V input.
- Schema side: manifest carries vs+fs only; DXVK needs compute/tess/geom slots (P3 schema v2).

**Rank: P2-NOW = route decision** (upstream-fix check + dxc-shader corpus assembly; corpus needs
dxc or extraction from a DXVK game — flagged as the offline constraint). Translator work is P3.

## (f) Barriers/pipeline/descriptors — record path incomplete [P2-NOW record, P3 schema]

Dropped at creation (all cheap to keep, all load-bearing for WebGPU pipeline construction):
- `pVertexInputState` (bindings + attribute formats/offsets/strides) — **without these the page
  cannot build a vertex layout; nothing draws**. P2-NOW.
- Push-constant ranges from `PipelineLayout` (DXVK pushes constants per-draw for everything) +
  no `vkCmdPushConstants` in the 85 (fits: 6 slots). P2-NOW record; schema field P3.
- `pMultisampleState` (samples + resolve) — WebGPU needs sampleCount at pipeline creation. P3
  (triangle is 1-sample; MSAA resolve P3 with it).
- Full depth-stencil (stencil ops, bias), per-attachment blend beyond `[0].blendEnable`,
  static viewport state, `pDynamicState` list. P3.
- Set-layout keeps (binding,type) only — no count/stageFlags/immutable/flags (update-after-bind).
  `vkUpdateDescriptorSets` records one object per binding — **no arrays** (`descriptorCount>1`
  takes element 0 only; DXVK writes texture arrays for descriptor indexing), no
  `dstArrayElement`, texel buffers / storage images lumped as view+sampler. P2-NOW: store
  arrays (`Binding.obj[]` + count).
- Per-draw state: viewport[1]/scissor[1] only (count>1, first≠0 dropped — DXVK sets both
  dynamically; single-viewport covers the triangle, P3 for the rest); dynamic-offset *values*
  dropped (record them — 2 slots — P2-NOW, DXVK uses dynamic UBO offsets); **no vertex/index
  buffer bindings, no `vkCmdDrawIndexed`** (DXVK draws ~100% indexed), no indirect/dispatch/
  compute/clear/copy/blit/resolve/fill/update commands, no queries, no secondary buffers.
  Indexed + VB/IB binding are P2-NOW (each ≤6 slots, pure recording); the rest is the P3
  command set.
- `resolveFrame` reads set 0 / bindings 0,1 only → DXVK frames (N sets, dozens of bindings,
  UAVs) serialize as ubo=null/texture=null. **P3 manifest schema v2** (N sets × M bindings +
  push constants + VB/IB + vertex layouts + sample count).
- Barriers: dropped with ordering marker — *correct* for a WebGPU consumer under immediate
  execution (layouts implicit; UAV/compute ordering already total). Revisit only with real
  multi-queue (P4) — do not "fix" early.

## Ranked gap ledger

**P2-NOW (before DXVK work starts — init wall + submit wall + record path):**
1. apiVersion 1.1→1.3 + DXVK device-extension advertisement (swapchain, maintenance5,
   robustness2, transform_feedback, depth_clip_enable, load_store_op_none; +maintenance6 iff
   targeting master) + instance `VK_KHR_win32_surface` (+debug_utils optional).
2. pNext-chain walker for Features2/Properties2 (+MemoryProperties2/QueueFamilyProperties2
   passthrough): robustness2 (nullDescriptor, robustBufferAccess2), maintenance5(/6),
   descriptor-indexing family, shader-int8/16/64, float16, scalarBlockLayout,
   transform-feedback, timeline(1.2), vk11/vk12 props; correct the core bits
   (imageCubeArray, independentBlend, shaderInt64, shaderFloat64? — verify vs DXVK's
   required-core set at transplant time).
3. Timeline-semaphore quartet (create-with-type, signal, wait, getCounter) + honor
   `VkTimelineSemaphoreSubmitInfo` in submit; present writes `pResults`.
4. `vkCreateWin32SurfaceKHR` (+ shim export + GIPA entry).
5. Hop outside `g_vkMutex` (present path restructure + locking rule comment).
6. Record path: `vkCmdDrawIndexed`, `vkCmdBindVertexBuffers`, `vkCmdBindIndexBuffer`,
   vertex-input state at pipeline creation, descriptor arrays, dynamic-offset values,
   `vkCmdPushConstants` recording (schema field can land P3, recording must exist to validate).
7. SPIR-V route decision (upstream-fix check + dxc corpus).

**P3 (D3D9 triangle gate):** manifest schema v2; binary-semaphore wiring; swapchain
recreate + formats/modes; sparse-queue verify; OOM cap; BDA/sync2/dynamic-rendering path
verification (implement-or-prove-unused); MSAA; clear/copy/blit/resolve/fill/update + indirect/
dispatch/compute command set; queries-as-counters; trap-volume measurement (unknown #3);
per-use-copy measurement (unknown #4).
**P4:** external win32 memory, present_wait/latency, real multi-queue, geometry/tessellation/
compute stages in schema, translator swap if naga can't be fixed, MAILBOX/IMMEDIATE, game-scale
memory (budget-aware).

**Deliberately NOT gaps:** `vk_host*` passthrough (wrong layer — P2 owns the ICD, no real
driver exists in-guest); loader/ICD-JSON/`VK_LOADER_DATA` (vacuous by design §2.0);
`getRamPtr`-based zero-copy (impossible on the soft MMU — §2.4 stands).
